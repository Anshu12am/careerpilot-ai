# Resume Projects Guide

## Why Projects Matter

Projects demonstrate practical application of technical skills. For students and
entry-level candidates, strong projects can provide evidence of hands-on
experience when professional experience is limited.

A project section should make it easy for a recruiter to understand what was
built, which technologies were used, what the candidate contributed, and what
the result was.

## What to Include for Each Project

Each project should ideally include:

- Project name
- Technologies used
- Short description
- Candidate's contribution
- Important features implemented
- Relevant technical concepts
- GitHub repository link
- Live demo link when available

## How to Write Project Descriptions

A project description should focus on what was actually built and what the
candidate contributed.

Weak description:

"Made a website using React and Node.js."

Better description:

"Developed a full-stack web application using React, Node.js, Express.js,
and MongoDB with user authentication and REST API integration."

The description should communicate both the technology and the functionality.

## Project Bullet Points

Project bullet points should generally begin with strong action verbs such as:

- Developed
- Implemented
- Designed
- Built
- Integrated
- Optimized
- Automated
- Deployed

Each bullet should communicate a meaningful technical contribution.

## Technologies

Mention technologies that were actually used in the project.

For example:

- React
- Node.js
- Express.js
- MongoDB
- Mongoose
- JWT
- Tailwind CSS
- Git

Do not add technologies simply because they are popular or relevant to the
project category.

## Features

Important technical features can strengthen a project description.

Examples include:

- User authentication
- Authorization
- CRUD operations
- REST APIs
- Database integration
- Search and filtering
- File uploads
- Email verification
- AI integration
- API integration
- Responsive UI
- Deployment

Only mention features that were actually implemented.

## Measurable Results

When genuine measurements are available, they can make project descriptions
stronger.

Examples:

- Reduced API response time
- Improved page loading performance
- Supported a specific number of records
- Reduced manual work
- Improved test coverage

Candidates should never invent metrics.

## GitHub Repository

A project repository should ideally contain:

- Clear project name
- README file
- Project description
- Technologies used
- Setup instructions
- Screenshots when useful
- Environment variable instructions without exposing secrets

The repository should contain clean and understandable code.

## Live Demo

A live demo can help recruiters quickly understand the project.

When available, include the deployed application link along with the GitHub
repository.

## Project Selection

Choose projects that demonstrate skills relevant to the target role.

For a web development role, projects can demonstrate:

- Frontend development
- Backend development
- Database usage
- Authentication
- API integration
- Deployment
- Problem solving

Two or three strong, relevant projects are generally more useful than a long
list of incomplete projects.

## Common Mistakes

Avoid:

- Listing projects without descriptions
- Adding technologies that were not used
- Writing extremely long descriptions
- Copying descriptions from other projects
- Including unfinished projects without explaining their status
- Adding fake metrics
- Providing broken GitHub links
- Providing broken live-demo links

## Project Checklist

Before adding a project to a resume, check:

- [ ] Project name is clear
- [ ] Technologies are listed
- [ ] Main functionality is explained
- [ ] Personal contribution is clear
- [ ] Important technical features are mentioned
- [ ] GitHub link works
- [ ] Live demo works if provided
- [ ] No technologies or achievements are falsely claimed
